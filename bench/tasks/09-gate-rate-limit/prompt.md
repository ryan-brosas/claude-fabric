gate-service has auth but no request limit, and one noisy client can still take the whole gate. Please add a sliding-window rate limiter middleware, run after auth, keyed by client IP plus method and path, with the limit and window coming from the config or `createApp({ rateLimit })`. A blocked request must answer `429` with `{ "error": "rate_limited", "retryAfterMs }` where `retryAfterMs` is how long until the oldest counted request leaves the window, plus a `retry-after` header carrying those milliseconds in whole seconds rounded up. Only accepted requests count, a request leaves the window once `windowMs` has passed since it, and the existing auth, logging and route behavior must stay as it is.
